# Workshop steps

Work through these in order. Discuss concrete alternatives and record decisions
before treating a step as complete. All steps are currently open.

| Step | Topic | Completion criterion |
|---|---|---|
| 1 | Audience, purpose, and deliverable | Agree who uses the handoff, what they receive, and what counts as success. |
| 2 | AI access and package context | Agree how an AI obtains the installed version, documentation, code, and runtime feedback, including chat-only use. |
| 3 | User interview | Agree the questions, pacing, coding-comfort choices, and handling of missing information. |
| 4 | Feasibility and scientific decisions | Agree how capabilities are verified, gaps are reported, and scientific choices are resolved. |
| 5 | Workflow standards | Identify authoritative standards and define required code organization, parameters, outputs, and rerun behavior. |
| 6 | Handoff draft | Write the opening prompt, reading instructions, and delivery checklist using confirmed decisions. |
| 7 | Worked examples and evaluation | Try fresh sessions against representative goals and coding-comfort levels; record failures and revisions. |
| 8 | Release and maintenance | Agree versioning, repository placement, documentation links, and responsibility for keeping the handoff current. |

## Step 1 discussion prompts

1. Is the primary user a scientist with an analysis goal, and which levels of
   MATLAB familiarity must the first version support?
2. Should the first version focus on adapting released workflows, composing new
   workflows from existing APIs, or both?
3. What must the user have at the end: a workflow plan, an editable script, or a
   script with evidence from an inspected test run?
